# Task Quality Rubric

Use this rubric before finalizing a task brief.

## Pass / fail checks

- Goal is specific and bounded.
- Deliverable states what will exist after completion.
- Files or surfaces are exact enough to start work without repo-wide discovery.
- Critical context includes the task-relevant source facts instead of only linking large docs.
- Acceptance criteria are observable.
- Verification includes commands, checks, or visible evidence.
- Out-of-scope guards against scope creep.
- Dependencies are real and minimal.
- Task is small enough for one focused implementation pass and one review cycle.

## Automatic fail conditions

- The brief says `TBD`, `later`, `see PRD`, or equivalent placeholder text.
- The implementing agent would need to read a full multi-page doc to understand basic behavior.
- The task mixes unrelated outcomes that should be split.
- Acceptance criteria cannot be checked without interpretation.
