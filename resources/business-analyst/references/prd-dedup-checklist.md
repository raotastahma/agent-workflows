# PRD Dedup Checklist

Run this before finalizing any PRD or BA handoff.

- Does each confirmed requirement have one canonical statement?
- Does the summary explain the product without re-listing all requirements?
- Do phase sections reference requirement IDs instead of repeating requirement prose?
- Are open questions kept separate from confirmed requirements?
- Did any assumption quietly become a requirement without explicit source support?
- Is every major rule traceable to the user or source docs?
- If the same rule appears in more than one section, is only one version detailed?
- Could the architect understand what is locked vs what is still open in under 5 minutes?
