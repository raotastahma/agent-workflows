# Verification Before Completion

- No "done" / "fixed" / "approved" / "ready" without fresh evidence.
- Fresh evidence = command run, direct file inspection, or observed user-flow result.
- Re-run the original failing path before claiming a fix.
- Review verdict -> cite the check or code path that supports it.
- Status transition -> name what was verified and what passed.
- Full verification not possible -> say what was not run and why.
- No confidence language instead of evidence.
- "Looks correct" is not verification.
- "Should work" is not verification.
- Report: checked / result / remaining risk.
