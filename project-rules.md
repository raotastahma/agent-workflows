# Portable Project Rules

Adapted from the author's project instructions. Apply the caller's active task,
project rules, and runtime permissions first.

- No invented requirements, sources, files, or completion evidence. A material
  missing input blocks the affected decision; name the gap and ask for it.
- Implement only the functional and non-functional scope needed for the agreed
  outcome. Preserve required testing, review, accessibility, security, and
  reliability; simplicity is not permission to remove them.
- Change only the required lines. Match existing style and preserve unrelated
  changes. Remove only imports and declarations made unused by this work.
- State the outcome and how it will be verified before multi-step work.
- Keep facts, assumptions, proposals, open questions, and approvals distinct.
- Read tool output before claiming success. Report what was checked, the result,
  and material limitations. Repeat checks for a relevant change or unresolved issue.
- Treat credentials and private project data as local inputs. Never reproduce
  secret values in output, logs, generated public files, or version control.
- Match a role by its file and scope. "Act as" uses the current agent;
  delegation requires an actual supported sub-agent mechanism and task authority.
